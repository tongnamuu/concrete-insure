# 로깅 지침

로그를 추가하거나 변경할 때 다음 기준을 따른다. 문서와 예시에는 프로젝트 상대 경로나 설정값을 사용하고 개인 작업 디렉터리를 넣지 않는다.

## 기록 기준

- `concreteinsure/diagnostics.py`의 공통 로거를 사용하고 JSON 한 줄에 이벤트 하나를 기록한다. 새 필드는 허용 목록에 명시한다.
- 시각은 UTC로 기록한다. 처리·큐 대기 시간은 밀리초(`duration_ms`, `wait_ms`), 진행·제한 시간은 초(`elapsed_seconds`, `timeout_seconds`)로 구분한다.
- `request_id`는 서버에서 생성한다. 백그라운드 작업과 도구 호출에는 원래 요청 ID와 `job_id`를 전달한다. 클라이언트가 보낸 ID를 신뢰하지 않는다.
- 요청의 HTTP 상태, 작업의 큐 대기·시작·진행·종료, 외부 서비스와 PDF 작업의 소요 시간, 오류 코드와 취소를 기록한다.
- NIM 호출은 `attempt`, `max_attempts`를 기록하고 `provider.retry`에 오류 코드와 `delay_seconds`만 남긴다. 재시도 시에도 요청 본문과 예외 원문을 기록하지 않는다.
- 제공자가 반환한 종료 사유와 토큰 사용량만 기록한다. 누락된 값을 추정하거나 과거 작업의 소요 시간을 소급해서 만들지 않는다.
- 작업 접수, 개별 호출 완료, 전체 작업 완료를 구분한다. 취소와 서버 재시작으로 인한 중단도 별도 상태로 기록한다.
- 화면의 간단한 진행 문구와 별개로 상세 단계와 시간 정보를 로그에 유지한다.

## 민감정보 보호

- 질문·상황 설명·검색어·약관 발췌·문서 텍스트·모델 추론 내용·파일명·파일 경로는 기록하지 않는다.
- 요청·응답 본문, HTTP 헤더, 쿠키, 인증정보, API 키, 원시 예외 메시지와 예외의 로컬 변수는 기록하지 않는다.
- API 경로는 실제 URL과 쿼리 문자열 대신 `/api/jobs/{identifier}` 같은 경로 형식으로 기록한다.
- 오류는 정해진 코드와 예외 유형으로 식별한다. 필드가 허용되지 않거나 값의 형식이 맞지 않으면 기록에서 제외한다.
- 진단 로그는 원본 자료와 검색 결과를 보관하는 데이터 저장소와 구분한다.

## 출력 기준

- 실행 로그는 서버를 실행한 콘솔의 표준 오류(`stderr`)에 즉시 출력한다.
- 파일 핸들러·파일 저장·순환 보관 기능을 추가하지 않는다. 로그 출력용 디렉터리나 환경변수도 만들지 않는다.
- 사용자 자료와 작업 결과를 보관하는 기존 데이터 저장소는 진단 로그 저장 용도로 사용하지 않는다.
- 로그 본문을 HTTP나 SSE로 공개하지 않는다. 화면에는 사용자에게 필요한 진행 상태만 전달한다.

## 변경 시 검증

- 요청·작업 ID의 연결과 동시 작업 사이의 분리를 확인한다.
- 성공·실패·시간 초과·취소·재시작 이벤트가 콘솔에 출력되고 로그 파일이 생성되지 않는지 확인한다.
- 입력 원문·키·임의 필드·원시 예외 메시지가 로그에 남지 않는지 확인한다.
- 로깅이 SSE 전달, 작업 취소, 원문 검증을 방해하지 않는지 확인한다.
- 관련 검사는 `tests/test_diagnostics.py`와 기존 실행 경로 검사에서 수행한다. 테스트 대역의 결과를 외부 서비스의 가용성 검증으로 표현하지 않는다.

## 조건부 에이전트 기록

- `agent.routed`: `agent=drug_evidence`, `decision=invoke|skip`, `reason=explicit_drug_name|selected_product|no_drug_information`.
- `agent.tool`: 고정된 도구 이름만 기록한다. 이름/제품 ID와 도구 입력·결과는 기록하지 않는다.
- `agent.completed`: 구조화된 완료 상태와 단계 수만 기록한다. 모델 사고 과정과 생성 문장은 출력하지 않는다.
- NAT 에이전트의 `verbose`는 끄고 별도 추적 exporter를 설정하지 않는다. 모델 도구 인자는 프레임워크 실행 전에 검증하여 검증 예외에 원시 인자가 노출되지 않게 한다.

## 제품 선택 재개

- `job.resumed`: 선택 대기에서 새 실행으로 이어졌음을 현재 작업 ID와 함께 기록한다. 원래 질문·선택 품목·검색어·저장된 맥락은 출력하지 않는다.
- 재개 구간에는 입력 분석의 `input` 단계가 다시 기록되지 않는다. 이후 성분 조사·검색의 소요 시간과 실패는 기존 이벤트로 확인한다.
