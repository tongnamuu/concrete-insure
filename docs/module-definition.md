# concreteInsure 모듈 정의

구현 규약은 [contracts.md](contracts.md), 현재 연결 구조는 [architecture.md](architecture.md)를 기준으로 한다. 보험금 지급 판단·청구 권유·질병 추정·약관 요약은 제공하지 않는다.

**입력은 텍스트 레이어가 있는 약관 PDF와 사용자 질문 또는 상황 설명이다.** 별도 질문 없이 설명만으로도 검색할 수 있다. 설명에 명시된 사고·차량·장소·행동·보험상품/특약 이름과 질병명·질병코드·약품명을 검색 요소로 사용한다. 질병이나 처방 정보는 필수 조건이 아니다. 검색어는 입력의 정확한 부분 문자열이며 사용자 역할·부상·과실을 새로 추정하지 않는다. 선택 제품이 없어도 상황 설명으로 조사할 수 있다. 사용자 진술을 확인된 진단으로 승격하지 않는다.

| 모듈 | 입력 | 출력 | 실행 방식 |
|---|---|---|---|
| 대화 맥락 | 서버의 최근 성공 발화·검증된 원문 | 길이가 제한된 후속 질문 맥락 | SQLite, 소유권·약관별 격리, 매번 전송 동의 |
| 문서 등록 | 사용자 약관 PDF | 문서 hash, 원문 문자/좌표 인덱스 | 별도 PDF 프로세스, 비동기 작업 |
| 입력 확인 | 사용자 발화/상황 설명/명시적 입력 항목 | 원문에 있는 검색 요소 | Nemotron + 입력 원문 부분 문자열 검증 |
| 제품 선택 재개 | 저장된 질문·검증 검색어·후보·대화 맥락 + 사용자 선택·새 전송 동의 | 같은 대화 항목에서 성분 조사부터 재개 | 서버 체크포인트, 입력 분석·후보 조회 생략 |
| 성분 근거 조사 에이전트 | 명시된 약품명 또는 사용자 선택 품목 | 선택 필요/근거 확보/근거 부족, 공식 원문·출처 | 조건부 NAT 내장 Tool Calling Agent, `lookup_products`·`inspect_product`, 필수 근거 확인 후 코드 종료 |
| PDF 검색 도구 | 검증된 검색어 ID/기존 hit ID | 원문 span/페이지/좌표 | PDF search/context 도구 |
| 약관 ReAct 에이전트 | 위 상태와 tool observation | 다음 허용 도구 호출 또는 종료 | Nemotron native tool calling |
| 보장 항목 연결 | 특약 조항 원문·제품 근거 | 보장 항목 존재·직접/성분 간접 연결·실제 보장 확인사항 | 규칙 기반 코드, 지급 판단 없음 |
| 원문 검증 | 검색 결과와 source span | 구조화된 인용/제품 사실 | 애플리케이션 코드, 자유문 생성 없음 |
| 결과 표시 | 검증된 결과 | 1:1 웹 화면/표준 PDF 주석 | PDF.js, native Highlight |
| 작업 관리 | 요청/취소 | 저장된 결과, SSE 상태 이벤트 | SQLite, NAT workflow, asyncio queue |

각 모듈은 독립된 입력/출력 함수를 가지며 별도로 테스트할 수 있다. 성분 에이전트는 NAT 함수로 별도 등록하며 명시된 약품명·선택 품목이 없으면 실행하지 않는다. 모든 모듈을 LLM으로 만들지는 않는다. 특히 원문 구간/좌표 계산/주석 작성은 결정적인 코드가 담당한다. ReAct는 검색 결과를 관찰한 뒤 주변 문맥을 더 읽을지 선택하는 곳에 적용한다. 최신 사용자 흐름과 NVIDIA 연결 구조도는 [README](../README.md#사용자-입력부터-nvidia-연동까지)에 있다.

## 성분 조사와 약관 검색의 완료 규약

성분 조사의 `inspect_product`는 선택된 품목 ID 하나를 받고 식약처 상세 응답의 성분·모든 가용 허가문서를 한 번에 검증한다. 각 원문과 출처 검증이 모두 성공한 뒤에만 근거 상태에 기록한다. 모든 미선택 약품명의 후보 조회 또는 모든 선택 품목의 필수 근거 조사가 끝나면 코드가 내부 `finish_evidence`를 호출한다. 이 도구는 모델이 선택하지 않으며 완료를 확인하기 위한 추가 NIM 호출도 없다.

제품 선택 대기는 서버의 입력·후보·대화 체크포인트를 사용한다. 사용자의 선택과 새 전송 동의가 있어야 성분 조사를 재개한다. NAT 그래프를 계속 실행해 두거나 질문 전체를 처음부터 다시 보내는 방식이 아니다.

약관 검색은 `search_policy`·`read_context`·`finish_retrieval`을 모델이 선택하는 별도 ReAct 루프다. 성분 에이전트의 자동 완료 조건을 약관 검색 전체의 완료 조건으로 사용하지 않는다. 두 경로 모두 결과 문장은 모델이 생성하지 않고 검증된 원문 구간을 애플리케이션이 직접 반환한다.

## 스킬 실행 경계

`skills/`의 `concrete-insure-source`는 상위 원문 처리 지침이고, `drug-ingredient-resolver`와 `pdf-iso32000-annotator`는 도구 지침과 JSON 입출력 규약이다. CLI 어댑터는 후자의 두 도구를 제공한다. 웹은 같은 Python 모듈을 직접 호출하며 스킬 CLI를 별도 에이전트 런타임으로 실행하지 않는다. SkillSpector는 별도 설치하는 개발용 정적 검사 도구다.
